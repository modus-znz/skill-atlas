Token cost

Two very different budgets, routinely conflated.

A listing cost is paid in the system prefix of every single request, whether or not the skill is used — it is only the name plus the description. A load cost is paid once, when the skill is actually invoked, and is the whole SKILL.md body. Estimates below use chars ÷ 3.6, the ratio measured across this corpus.

The second billed listing — resident agents

Added as a fourth scan root on 2026-09-06. Everything above this point measures the skill listing and its {{ metrics.listing_budget_tok }}-token budget. The agent roster is a separate standing cost, drawn from its own allocation — so it is reported here beside that budget and deliberately never added into it.

The headline: {{ metrics.agents }} residents cost {{ metrics.agent_listing_tok }} tokens in every request, against {{ metrics.listing_tok }} for all {{ metrics.listing_entries }} listed skills and plugins combined. The roster is roughly a third again on top of the skill listing, and until this root existed the census could not see it at all — the true standing cost of the prefix was being under-reported by that whole amount. It is money well spent at this size, and the measurement is a pleasing independent check on the hand-made one: CLAUDE.md has long carried a ~1.3k tokens per session estimate for the roster, and a scan that had never been pointed at the directory puts it at {{ metrics.agent_listing_tok }}. The number worth watching is the marginal one: {{ metrics.agent_listing_tok_each }} tokens per resident, paid on every request for the life of the install. The roster has no equivalent of the vault — there is no place to park an agent where it stays reachable but stops billing, so unlike a skill, an agent you install is an agent you pay for. Twenty-one is a sound call at this price; the guardrail is simply to add the twenty-second deliberately rather than by habit, and to evict on the same terms.

Agents carry no grade anywhere in this report, and that is a design decision rather than a gap. Three of the six rubric dimensions are structurally pinned for them — depth is always stub because an agent is a single file by design, reach has no listing state to grade, and hygiene measures a duplication mode they cannot have. A score built from the surviving three would still print beside skill grades and invite a comparison that means nothing. Better a visible n/a than a confident number measuring the wrong thing. Their {{ metrics.agent_bytes_kb }} KB of prose is instead held to the one standard that does transfer: every resident has a real description, and {{ metrics.agent_desc_missing }} are missing one.
