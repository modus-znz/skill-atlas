The Android release keystore and its password are committed and pushed

SecurityAction required

Found while writing capacitor-mobile-build — not something the skill census would ever have surfaced, because it is not a skill problem. android/app/build.gradle declares the release signingConfig with the store and key passwords in plaintext, and that file plus both copies of modus-release.jks are tracked and pushed to git@github.com:dealtfel/Modus-FM-App.git. The root .gitignore does carry android/app/*.jks, but the rule is inert: gitignore never applies to an already-tracked file. Anyone with read access to that repo can sign a build Android will accept as genuine.

Fix — and deleting the files is not enough. They remain in history, so the key must be treated as compromised: generate a new keystore and re-key, then either purge history or rotate the upload key through Play App Signing. Going forward, read the credentials from an untracked android/keystore.properties at build time rather than declaring them in build.gradle. The correct shape is documented in capacitor-mobile-build; the password itself was deliberately never copied into any skill, note, or into this report.

Fix: split it.
