A shallow clone hides its own staleness

Vault collections are commonly brought in as single-commit snapshots — squashed, or clone --depth=1 — with no upstream remote configured. A snapshot has no upstream to drift from, so git pull is a no-op and nothing locally ever disagrees with anything. The staleness is invisible by construction rather than merely unfixed, which is why it has to be checked deliberately. Two consequences worth knowing before you try to refresh one in place:

  • Sparse and shallow do not combine well. Expanding a shallow sparse checkout in place can hang on read-tree or refuse merge --ff-only. A fresh clone --depth=1 into a temp directory and a directory swap is faster and more predictable than repairing one.
  • Counting files does not tell you whether you are behind. A collection checked out sparsely, or filtered by a read-tree exclusion, will legitimately hold fewer skills than upstream ships. That gap is a scope difference, not drift, and a census that cannot see the exclusion list will report it as staleness. Check the exclusion before concluding anything.
  • Enumerate what upstream ships but you did not take. A clone frequently brings skills, agents, specs and templates in the same tree, and a skills-only clone quietly drops the rest.

Order of operations, when refreshing

Fix reachability before adding volume. Pulling more skills into an index that keeps one winner per id makes the library larger and no more useful, because the new skills collide with the old ones. Namespace the ids first, then refresh, then confirm nothing new landed already shadowed — the Reachable column above is that check.

Licensing

Not every collection that is publicly readable is redistributable. A repository can be source-available — readable, clonable, and explicitly not permitted to be republished — and a skill library is exactly the kind of thing that gets mirrored, synced between machines, or published as part of a dotfiles repo. Check the licence of any collection before it lands somewhere that is mirrored, and keep source-available material out of anything that propagates automatically.
