Configuration

What decides reachability, and what quietly changes the bill.

Reachability mechanics worth remembering

  • Visibility overrides do not apply to plugin skills. Hiding is only available for skills in your own skills directory. A plugin is all-or-nothing: enabled means every one of its skills is listed, at full description cost. There is no per-skill middle ground, so a plugin is priced as a unit.
  • Hidden is not disabled. The {{ metrics.hidden }} overridden skills work exactly as before — they are absent from automatic selection and reachable by name or by search. Hiding changes what is paid for by default, not what is available.
  • A search index that excludes the plugin cache is not missing anything. Plugin skills cannot be hidden, so they are already in the listing; indexing them too would only duplicate it. If your index deliberately skips them, a low plugin count there is expected rather than a gap.
  • Project settings can re-enable a family. A family you hid globally can be re-listed in a single repository's settings, so it is listed where the work happens and hidden everywhere else. That is the right pattern for a skill belonging to one codebase, and it beats a global switch in both directions. Note the cost: a re-listed skill pays its description in that repository's every session, so a longer description written for discoverability is not free there.

A hook can turn an on-demand skill into standing cost

A skill that is only paid for when it loads is cheap by construction. A hook that injects a skill's body into every session removes that property entirely: the file is now a fixed per-request tax, paid whether or not the work needs it, and it will not appear in any listing-cost figure because the listing is not where it is billed. This is the one place a library can acquire a large recurring cost without any configuration in the skills directory changing.

The audit that catches it is cheap: list the hooks wired to SessionStart and to PostToolUse, and for each one that injects content, treat that content as a listing cost and account for it next to {{ metrics.listing_tok_active }} tokens of skill listing. Hooks that only verify something and inject a short rule are fine; the expensive shape is a hook that injects a reference document.
