Three live hooks for a machine running 25 projects is lean, and deliberately so — the claude-mem evaluation was rejected specifically because it wanted five more, including a PostToolUse on every call. That decision holds. Two additions would still earn their keep, both cheap:

  • A PreToolUse guard on destructive Bash — rm -rf outside the scratchpad, git push --force, DROP DATABASE. CLAUDE.md already forbids all three in prose; a matcher makes it structural rather than advisory.
  • A SessionEnd reminder running rotate-active-status.py --check. The memory rule is the one guardrail that depends entirely on remembering to run a script at the end of a long session, which is precisely when it is most likely to be skipped.

Reachability mechanics worth remembering

  • skillOverrides does not apply to plugin skills. Hiding is only available for ~/.claude/skills/. A plugin is all-or-nothing: enabled means all its skills are listed, at full description cost.
  • Hidden is not disabled. The {{ metrics.hidden }} overridden skills work exactly as before — they are absent from the model's automatic selection, and reachable by /name or skill_search.
  • The skill-router MCP excludes the plugin cache by design — plugin skills are never hidden, so indexing them would only duplicate the listing.
  • Project settings can re-enable a family. odoo-* is already re-listed inside /opt/odoo19-custom-addons/ and nowhere else. This is the right pattern for figma and expo too, rather than a global switch.
