--- id: overview title: Overview ---

This report is a census of a Claude Code skill library, taken by walking the filesystem rather than by trusting the documentation. It finds {{ metrics.total }} distinct skills and {{ metrics.agents }} resident subagents — {{ metrics.total_units }} units in all, drawn from {{ metrics.files_scanned }} files on disk. Where that file count exceeds the unit count, the difference is {{ metrics.stale_copies }} superseded copies of the same unit, not extra capability: they are counted, flagged, and excluded from every score below.

Every count, score and token figure below is interpolated from this run's data. There is no prose anywhere in this report holding a number that was typed by hand, so nothing here can quietly go stale behind your back. The sections that are written in words say what to look for and where to look — they do not assert what is true of your library, which is the part no scan can know.

What this audit checks for

Four failure modes worth knowing about, and where each one is measured.

Superseded copies read as capability

Census

Plugin caches and versioned roots keep every previous release on disk. Counting files counts the same skill several times, and a scan that does not collapse them will report a library larger than the one the model can actually reach. This run found {{ metrics.stale_copies }} superseded copies beyond the {{ metrics.total_units }} live units. The per-skill list flags each one.

Where: the Every skill panel, and the stale column in the exported data.

Visibility is the cheapest lever you have

Cost

A hidden skill costs nothing in the session prefix. This library lists {{ metrics.listed }} active skills for {{ metrics.listing_tok_active }} tokens per session, and holds {{ metrics.hidden }} more hidden. Hiding those {{ metrics.listing_avoided_n }} avoided {{ metrics.listing_avoided_tok }} tokens of listing cost, which would otherwise be billed on every single request. That is the single largest deliberate saving available, and it costs nothing but a line of configuration.

Where: the Token cost panel, including what the listing would look like with every hidden skill reversed.

A skill nothing can select is not capability

Reachability

Reachability is the axis that decides whether an installed skill does any work. A skill that is installed, well written, and unreachable from every selection path is costing you disk and maintenance for nothing. This run sees {{ metrics.listed }} skills in the automatic listing and {{ metrics.vault }} in the vault, which is addressable by search rather than by the listing. If the skill-router index is available, its own id map is read directly and reachability becomes measured; without it, router-dependent counts are reported as not measured rather than as zero.

Where: the Health panel. A shadowed skill — present on disk, but outranked by another with the same id — is the specific case worth hunting.

Proportion is a judgement this tool will not make for you

Coverage

The scan can tell you a family holds 40 skills and another holds 1. It cannot tell you whether that is wrong, because “wrong” is defined by what you are building, and that lives in your projects rather than in ~/.claude. So this report deliberately stops at size, spread and cost. If you want density verdicts, the supported way to add them is a narrative fragment under content/ with the figures it depends on declared as assertions — then the tooling will tell you when your own claim goes stale.

Where: the Families panel gives size and per-family spread; atlas doctor lists anything that landed in Unclassified so you can classify it yourself.
