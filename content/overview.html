What the scan changed

Five claims in the current documentation that the measurement contradicts.

claude-router undercounts the plugin cache

Doc drift

The router records hyperframes at “~19 skills” and expo at “~21”. Two sizeable plugins — figma (14) and ui-ux-pro-max (7) — carry no count at all. The counts were taken from raw directory listings at some point and the cache has since grown extra version folders underneath them.

Fixed 2026-09-04 Corrected in claude-router from the live install paths in installed_plugins.json, not from the cache tree: 24 plugins, 93 plugin skills — expo 24, hyperframes 20. Note the census itself over-counted here: collapsing by (plugin, skill) across all cached versions unioned skills that the current release had already dropped, which is how hyperframes read 26. Post-prune only the live version survives, so 20 is the number a session can actually reach. Two further findings fell out: commit-commands and code-review are commands-only plugins with zero skills, making the commit-commands:* override keys definitively inert rather than merely suspected so; and the hidden-skill count was itself stale — 105, not 101, now corrected in both claude-router and CLAUDE.md.

Fix: regenerate the plugin table from a dedupe-aware scan rather than a find | wc -l, and note the version each count refers to.

1.5 GB of plugin cache, and most of it is superseded

Disk

claude-plugins-official holds 1.1 GB and video-prep another 441 MB. expo keeps three versions side by side (1.11.0 / 1.12.0 / 1.12.3), hyperframes three (0.8.3 / 0.8.4 / 0.8.6), chrome-devtools-mcp two. frontend-design and skill-creator are each cached under seven hash-named directories.

Fixed 2026-09-04 1,522 → 755 MB; 767 MB reclaimed, 47 superseded version directories across 10 plugins. The “worse” above was wrong — those seven hash dirs are ~1 MB each, pure trivia. The weight was in three directories: chrome-devtools-mcp/1.7.0 at 265 MB and two stale hyperframes builds at 363 MB, all three fat because they vendor a browser or a node_modules tree. The keeper for every plugin was resolved from installed_plugins.json and asserted to exist and be non-empty before a single delete ran; all 24 plugins were re-checked afterwards and still resolve.

Fix: keep the newest version per plugin and delete the rest. Nothing references the old folders; the loader resolves the current version from the marketplace manifest.

Hiding 104 skills is working, and it is worth 5,603 tokens a session

Confirmed

Updated 2026-09-04 The listed active skills are now {{ metrics.listed }} costing {{ metrics.listing_tok_active }} tokens of name-plus-description in every session prefix — capacitor-mobile-build (row 9) was deliberately left listed so mobile build work selects it automatically, at ~102 tokens; odoo-deploy (row 7) was registered hidden instead, so it costs nothing outside the addons repo. The {{ metrics.hidden }} hidden ones would add {{ metrics.listing_tok_hidden }} more — the single largest deliberate saving on the machine, and it more than doubles the listing if reversed. The skillOverrides strategy is sound and should be extended, not relaxed.

77 vault skills are installed and structurally unreachable

Reachability

Read from the router's own index, not inferred. lib.mjs keyed every skill by slugify(name) — a bare name, no collection prefix — and buildIndex kept one winner per id under a precedence of active > plugin > vault. Because skill_search iterated that same winners-only map, a shadowed skill was absent from search results as well as skill_load: unreachable at all, by any spelling. Index at census time: 765 ids — 149 active and 616 of 693 vault skills. financial-services was worst hit, with only 17 of its 57 reachable; knowledge-work lost 23. Ties between two vault copies broke on filesystem enumeration order, so which copy survived was not even a policy decision.

Fixed 2026-09-04 Ids are now qualified as collection/name, claiming the shortest unused form and escalating to deeper path prefixes on collision; active skills keep the bare name. Files are sorted per root before ids are assigned, so enumeration order no longer decides anything. Every one of the 765 bare names still resolves — to the highest-precedence copy, which now also reports its siblings as variants, so choosing a specific copy is deliberate rather than silent. Index: 842 ids, 149 active + 693 vault, nothing dropped. financial-services serves all 57.

Fix: namespace vault ids as collection/name and let skill_search emit every match with its prefix. The winner set is already tracked — each item carries a shadowedBy array that is populated and then never surfaced through the MCP.

Coverage is inverted against the actual project mix

Coverage

Measured against the 27 project roots: 377 skills in corporate, knowledge-work, financial-services and openaccountant serve essentially one project (bizflow). Meanwhile Odoo — the largest codebase on the machine — has 7; Capacitor and Android native have none; the three infrastructure projects (k8s, MikroTik, router) have none. The library is broad where the work is thin and thin where the work is deep.

Acted on 2026-09-04 Two skills written, both sourced from what is on disk rather than invented. odoo-deploy — the family had seven skills for talking to Odoo and none for applying a change: upgrade-vs-restart by change type, both instances (8069/odoo and 7079/laicidev), the sudo -S-plus-stdin-redirect trap, and the failure patterns. capacitor-mobile-build — build/sync, emulator smoke test, the 10.0.2.2 host mapping, logcat channels and the signed release, drawn from the real capacitor.config.ts, npm scripts and build.gradle. Odoo 7 → 8, Capacitor 0 → 1. Infrastructure still has none — deliberately out of scope.

Fix: the highest-value skills to write are Odoo-side (ORM patterns, QWeb views, migration scripts) and Capacitor build/release — not more of what is already installed.
